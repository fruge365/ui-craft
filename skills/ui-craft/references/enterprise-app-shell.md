# 企业应用壳层与权限界面

企业后台「中规中矩」通常不是视觉问题，而是**壳层缺了企业软件必须具备的几件事**：权限可见、操作可审、命令可达、列可配置。这四件事做到位，界面自然显得专业；做不到，再漂亮的配色也只是换了皮的表格。

## 壳层的固定构件

| 构件 | 必须回答的问题 | 常见缺失 |
| --- | --- | --- |
| 组织切换器 | 我在哪个租户/组织下操作？ | 只在设置页出现，导致误操作跨组织 |
| 导航分区 | 权限不同的人看到的导航是否不同？ | 全部可见但点进去报 403 |
| 顶栏 | 当前路径、同步状态、全局命令入口 | 只有 logo 和头像 |
| 内容区 | 主任务 + 参考信息并置 | 参考信息被迫来回跳转 |
| 审计区 | 我刚做了什么、谁改过 | 全靠事后查日志系统 |

**导航要按权限渲染，而不是点进去才拒绝。** 无权限的模块直接不出现，或用禁用态加锁图标并说明原因。让用户点进去撞 403 是设计缺陷。

**组织上下文必须常驻可见。** 多租户产品里最危险的操作错误是"在错误的组织下改了数据"。组织名放在导航顶部，且随操作一直可见。

## 权限建模：按数据，不按界面

最可靠的做法是让每一行数据自带能力字段，界面从数据读权限，而不是写一堆 `if (role === 'admin')`：

```js
// 每行携带当前账号对它的能力，界面据此渲染
const row = { id: 'ds-1001', cap: 'edit' | 'read' | 'none' };
```

**三条实现纪律：**
1. **能力决定控件，不是决定提示。** `cap !== 'edit'` 时，编辑入口要么不渲染，要么真的 `disabled` 并加锁图标 + 原因，不能只弹"权限不足"。
2. **批量操作要能解释跳过。** 跨权限批量选中时，界面必须明确说"已选 12 项，其中 3 项受限将跳过"，并在执行后确认跳过数。
3. **只读也要给出下一步。** 受限状态下提供"申请权限"入口，写清审批人，而不是让用户自己去找。

**敏感级别要显式标注。** PII、财务、受控这类标签不是装饰，它解释了为什么这行不能编辑、为什么导出会被拦截。用一致的色板与文字，不要只用图标。

## 命令面板

企业系统里一个有权限的用户要跨 8 个模块找同一个对象。命令面板把"找"变成一次按键。

- **入口固定**：顶栏一个可见按钮 + `⌘K` / `Ctrl+K`。
- **同时搜命令与对象**：命令（新建、导出、切换范围）与数据对象（数据集、单据、人员）混排，各带类型标识。
- **键盘优先**：`↑↓` 选择、`Enter` 执行、`Esc` 关闭，全部可用键盘完成。
- **空结果要给下一步**：列出最接近的 3 个对象，而不是只写"无匹配"。
- **执行后要有回执**：面板关闭并给出 toast 或状态变化，不能静默消失。

**不要把所有功能塞进命令面板。** 面板是**加速器**，不是唯一入口。主导航仍要完整。

## 表格：企业界面的主战场

| 能力 | 为什么必须有 | 实现要点 |
| --- | --- | --- |
| 排序 | 用户按不同维度判断优先级 | 表头可点，当前列有 `aria-sort` 与方向图标 |
| 列配置 | 不同角色关心不同列 | 记住本机选择；至少能隐藏 2 列 |
| 密度切换 | 大屏看少、笔记本看多 | 紧凑/舒适两档，热区不变 |
| 粘性表头 | 长列表滚动后仍知道列含义 | `position: sticky` + 正确的 z-index |
| 批量选择 | 例行操作一次处理多项 | 本页全选 + 跨页保留，且有"已选 N 项"常驻 |
| 行详情 | 不离开列表查看细节 | 侧边抽屉优于整页跳转，保留列表位置 |
| 空状态 | 区分"没数据"与"没权限" | 两种插画与文案不同 |

**行点击与复选框要分开。** 点勾选框不应打开详情；点行应打开详情。两者在同一行时，勾选框区域要阻止事件冒泡。

**抽屉优于跳页。** 企业用户常在对比多行，整页跳转会丢失位置。抽屉宽 400—480 px，右侧滑入，`Esc` 关闭，焦点在打开时移入、关闭时归还给触发行。

## 审计轨迹

**写操作必须留痕，且用户能看到。** 不是给合规部门看的日志，是给操作者自己核对的。

- 位置：右侧常驻面板（宽屏）或抽屉（窄屏），不要藏在设置里。
- 内容：谁、做了什么、对哪个对象、结果如何（成功/被拒）、时间。
- 拒绝也要记录。"尝试导出但被策略拒绝"是比成功更有价值的信息。
- 实时更新：操作后立刻出现新条目，不需要手动刷新。

**审计只读。** 不允许在审计面板里编辑任何东西。它是一份证据，不是操作入口。

## 企业级视觉的具体判断

| 维度 | 企业后台的做法 | 避免 |
| --- | --- | --- |
| 底色 | 极浅中性灰（#F7F8FA），内容区纯白 | 大面积米黄/米白（显得像文档） |
| 导航 | 深色（#131A24），与内容区形成强对比 | 浅色导航 + 浅色内容（层次消失） |
| 字号 | 正文 12—13 px，表头 10—11 px 大写间距 | 正文 15 px 以上（信息密度不够） |
| 圆角 | 6—8 px，克制 | 16 px 以上（显得像消费级产品） |
| 阴影 | 仅用于浮层与抽屉 | 卡片都用阴影（层次泛滥） |
| 分割 | 1 px 细线（#EEF1F4） | 粗边框、重底色斑马纹 |
| 强调色 | 一个主色（操作）+ 一组语义色（状态） | 每个模块一个颜色 |

**密度即专业感。** 企业用户一天看几百行，把行高从 40 px 压到 32 px、字号从 14 降 12，专业度立刻上升。前提是点击热区在触屏上仍有 44 px（用内边距补，不靠行高）。

**不要做成消费级。** 消费级产品的圆角、渐变、动效、留白在企业场景里会降低信息密度并显得轻浮。企业界面的"高级感"来自**精确对齐、克制用色、一致间距**，而不是装饰。

## 验证

- 用三个不同权限的账号各走一遍主路径，确认导航与控件都随权限变化。
- 批量操作混合权限项，确认提示写明跳过数与原因。
- 只用键盘完成：搜索对象 → 打开抽屉 → 修改 → 关闭 → 在审计里确认留有记录。
- 表格滚到第 5 页，确认表头仍可见、已选项仍保留。
- 断网后执行一次写操作，确认给出明确失败与重试路径，且不产生"看起来成功了"的假象。
- 把浏览器缩放 200%，确认表格仍可用（可横向滚动，不裁切关键列）。
