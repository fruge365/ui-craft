# 自助终端、POS 与手持设备

这类设备的共同点：使用者站着、可能有排队的人在看、往往戴着口罩或手套、只用一根手指。设计目标是让人一次做对，而不是让人探索。

## 自助终端与排队机

| 环节 | 要点 | 常见错误 |
| --- | --- | --- |
| 起始 | 用一句话说明「这里能办什么」，并给出证件或扫码入口 | 直接把科室列表铺满屏，人先找不到自己在办哪件事 |
| 选择 | 时段、座位、窗口用等宽网格；不可选项置灰并给出替代去处 | 只把已满时段变灰，不说明还能去哪 |
| 变化 | 选择后小结区同步更新，位置固定不跳动 | 小结在页面底部，改选后需要回头看 |
| 确认 | 主按钮只保留一个，次要动作退后 | 三个同等重量的按钮并列 |
| 回执 | 出票、打印、电子凭条三选一，写明凭条去向与超时时间 | 打印后不说明取走时限 |

**触控与视线。** 站立操作时按钮高度不小于 48 px，主操作放在屏幕中下 1/3 处，避免抬手过高。室外或靠窗设备的玻璃反光很重，正文对比度按 ≥ 7∶1 设计，并准备暗色高对比版本。

**排队心理。** 首要任务必须在 3 步内完成；每步都显示「第几步 / 共几步」。支付环节给出总价与单价的并列，不做隐藏加价。

**打印与网络。** 打印失败、网络超时、证件读取失败是常态而非异常。每种失败都要给出「重试 / 换证件 / 去人工窗口」三条出路，且不能吞掉已填内容。

## POS 收银台

**双屏职责分离。** 店员屏放明细、数量、折扣与快捷操作；顾客副屏只显示金额、件数与支付方式。两边数字必须来自同一份状态，副屏不能自己算一遍。

**扫描优先。** 操作员九成时间在扫，不在打字。扫描输入框自动聚焦，回车即加入；扫错码给出明确拒绝并保留输入以便修正，不能静默失败。

**快捷键要能被手套压到。** 常用动作（加入、改数量、收款、作废）保留实体键位或大热区；破坏性动作（作废整单）与常用动作之间留出间距，并二次确认。

**离线与撤销。** 断网时本单要能继续录入并在恢复后补传；作废与退款必须留审计记录，不能只有「已作废」一句话。

## 手持终端（PDA）

**手套与强光。** 热区 ≥ 44 px 并留间距；对比度按户外直射设计，避免浅灰字。补光、放大镜、语音播报是三个真实需要的开关。

**一次扫描一个回执。** 成功即改变行状态并推进到下一行；重复扫描不累加、不报错堆叠，而是明确说「已经盘过」。

**物理键与触屏并存。** 侧键扫描、方向键移动、确认键提交；屏幕上同类动作也要可点。二者触发同一段逻辑。

**差异永远可见。** 应盘与实盘的差异行用颜色加符号双通道标出，列出差异数量，而不是只把行标红。

## 墨水屏与电子价签

**刷新是代价。** 整屏刷新会闪黑（约 0.3—1 秒），局部刷新会留浅影。首屏与详情切换用整刷，同一页面内的数值变化用局部刷新。

**一位元灰阶。** 没有动画、没有悬停、没有半透明层。层级只能靠字重、字号、留白与反白块建立。

**远读优先。** 价签的主要读者站在 1—1.5 米外：价格数字最大、单位价其次，规格与编号能读即可。促销标记占一行，不压价格。

**断电保持。** 页面必须假设「最后一次刷新后不再更新」。所有时间、电量、批次信息都当作快照写清，不写「刚刚」。

## 验证

- 用 1280×800 与 1080×1920 两种竖横姿态各排一次，确认主按钮不被安全区或支架遮挡。
- 关掉鼠标，用键盘 Tab 与 Enter 走完主路径；再用单指点击走一遍。
- 模拟断网、打印失败、重复扫描、证件读取失败，各检查一次恢复路径。
- 在 30% 亮度与 100% 亮度下分别读主数字。
- 让另一个没看过设计稿的人在三步内完成一次办理，记录卡住的位置。
